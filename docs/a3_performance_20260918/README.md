## 設定與計時解讀

- 板端回報 CPU 800 MHz、主系統匯流排 400 MHz。
- 本機驗證專案設定：CPU 資料快取與指令快取均為 1；USE_OVERDRIVE=1；UART=921600。
- 設定檔註解中的 NPU 1 GHz 是配置目標；本次未獨立讀回 NPU 時鐘配置暫存器。
- 原始碼列出 MCU 計数順序為 cpu_start、cpu_core、cpu_end；完整匹配片段與來源雜湊見 source_context.json。
- CPU cycles 的數值不直接當作 CPU 忙碌率或 NPU 硬體使用率。
- 一般模式與逐區塊模式分別記錄；兩者差值不直接作為量測開銷。

## 結論與限制

- 固定輸入、暖機後的一般推論約 48.61 毫秒，三組結果接近。
- 攝影機管線的主要耗時集中在擷取等待與完整模型執行。
- uart_ms 包含格式化、遮罩計數與傳送，並非只有線路傳輸時間。
- 減少日誌可能改變下一次擷取的時序，不能直接相減推算新幀率。
- 攝影機基準使用毫秒計時；0 毫秒不代表完全沒有成本。
- 顯示時間量到更新提交；感測器丟幀數尚未量測。
- 這是短時間基準；冷啟動與長時間穩定性仍屬 A5。
- 下一步 A4：固定模型、輸入與量測條件，進行受控記憶體配置比較。
